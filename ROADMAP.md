# План: единая схема расчёта для любых предприятий

Сейчас расчёт в «Наряде» повторяет правила одного завода. Чтобы приложением могли пользоваться рабочие других
предприятий, правила нужно вынести из кода в настраиваемую **схему оплаты**. Текущие правила при этом останутся
вариантом по умолчанию, и у нынешних пользователей ничего не изменится.

## Что сейчас зашито в код

| Правило | Как сейчас | Где |
|---|---|---|
| Способ оплаты | повременный: ставка × часы присутствия; нормо-часы на деньги не влияют | `SalaryCalculator.calculate` |
| Задержки | до нормы месяца — ×1, сверх нормы — ×2 | `SalaryCalculator.calculate` |
| Выходные и праздники | всегда ×2, без варианта «×1 + отгул» по ст. 153 ТК | `isRegularDay`, `fixedDoubleHours` |
| Сверхурочные по ТК | нет «первые 2 ч ×1,5, дальше ×2» (ст. 152) | — |
| Ночные часы | не учитываются (ст. 154: доплата от 20 %) | — |
| Норма месяца | рабочие дни по графику × часы смены; праздники РФ отмечаются вручную | `scheduledNormHours` |
| Графики | только 5/2 и 2/2 с одной длиной смены | `WorkSchedule`, `isScheduledWorkDay` |
| Аванс | часы смен с 1 по 15 число × договорная ставка | `calculateAdvance` |
| Разряды | только 3–6, на оплату не влияют | `Operation.grade`, `BackupCodec.validate` |
| Банк нормо-часов | лимит = часы месяца × коэффициент (практика одного завода) | `BankRepository` |
| Удержания и надбавки | нет НДФЛ, премии, районного коэффициента — только «грязная» сумма | — |

## Целевая модель

Одна сущность **`PayScheme`** (таблица или поля настроек) вместо констант в `SalaryCalculator`:

```
PayScheme
  payMode: HOURLY | PIECE | PIECE_BONUS     — повременная / сдельная (нормо-часы × тариф разряда) / сдельно-премиальная
  gradeRates: Map<разряд, ставка или коэффициент>  — тарифная сетка 1–8 разрядов
  overtime: NORM_MONTH | LABOR_CODE | NONE  — «сверх нормы ×2» (как сейчас) / ×1,5 первые 2 ч, затем ×2 / без доплат
  overtimeFirstRate, overtimeNextRate, overtimeFirstHours
  weekendRate (×2), holidayRate (×2), weekendCompOffAllowed
  nightRate (+20 %), nightFrom, nightTo
  advance: HOURS_FIRST_HALF | PERCENT | FIXED, advanceDay, advancePercent, advanceFixed
  bonusPercent, regionalCoefficient, northernAllowance
  incomeTaxPercent (13 %) — показывать «на руки»
```

`SalaryCalculator` получает схему параметром. Нынешнее поведение — пресет **«Как сейчас (по умолчанию)»**:
повременная оплата, сверх нормы ×2, выходные ×2, аванс за 1–15 по договорной ставке.

## Этапы

### Этап 1 — минимально нужное другим предприятиям

1. **Схема оплаты в данных.** Сущность `PayScheme`, миграция с пресетом «Как сейчас», поля в резервной копии
   (с умолчаниями для старых копий), тесты: на старых данных результат расчёта не меняется ни на копейку.
2. **Сдельная оплата.** Режим, в котором зарплата = нормо-часы за месяц × ставка разряда (тарифная сетка).
   Часы присутствия остаются для табеля и нормы.
3. **Сверхурочные по ТК.** Вариант «первые 2 часа ×1,5, дальше ×2» для дневного учёта и ×2 сверх нормы для
   суммированного учёта (как сейчас). Коэффициенты настраиваются.
4. **Производственный календарь РФ.** Встроенный список праздников и сокращённых предпраздничных дней на год,
   с обновлением в новых версиях приложения. Ручные отметки дня остаются главнее.
5. **Мастер первой настройки.** Три вопроса вместо формы: «как вам платят» (повременно / сдельно), график,
   сверхурочные. Предлагает пресет, всё можно поправить в настройках.

### Этап 2 — точнее зарплата

6. **Гибкие графики**: 1/3, 3/3, 4/4, день/ночь, произвольный цикл из N дней, своя длина смены для каждого дня цикла.
7. **Ночные часы**: поле в окне часов («из них ночных»), доплата по схеме.
8. **Премия и надбавки**: процент премии, районный коэффициент, северная надбавка.
9. **«На руки»**: удержание НДФЛ и прочих процентов, отдельная строка в отчёте.
10. **Аванс по-разному**: фиксированная сумма, процент от оклада, часы × ставка, свой день выплаты.

### Этап 3 — удобство и распространение

11. **Пресеты предприятий**: экспорт и импорт схемы отдельным файлом — бригадир настраивает один раз
    и раздаёт коллегам.
12. **Банк нормо-часов** как необязательный модуль со своими параметрами (уже отключается в экспериментах).
13. **Единицы выработки**: штуки, метры, килограммы — у операции.
14. **Отчёт для сверки с расчётным листком**: построчное сравнение с тем, что начислил работодатель.

## Как делать, чтобы ничего не сломать

- Каждое правило — сначала в схему с текущим значением по умолчанию, потом интерфейс.
- Миграции только добавляют поля; формат резервной копии растёт с умолчаниями для старых версий.
- На каждый режим — модульные тесты `SalaryCalculator` с примерами из реальных расчётных листков.
- Новые режимы сначала прятать в «Экспериментах», как банк и аванс с переработками.
- Тексты в интерфейсе — нейтральные: «норма», «схема оплаты», без названий конкретного завода.

## Порядок работ

1 → 2 → 3 дают приложение, которое честно считает зарплату большинству сдельщиков и повременщиков.
4 и 5 снимают ручную работу при первой настройке. Остальное — по отзывам пользователей из RuStore.
